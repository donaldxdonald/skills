# Copy Density Audit

## Principle

Expose the workflow before explaining it. Visible UI copy should help the user act, understand state, or recover from a problem; everything else should be removed, shortened, or moved into progressive disclosure.

## Modes

- **Design Mode**: before implementation, set a copy budget and choose UI structures that prevent explanatory paragraphs.
- **Audit Mode**: after implementation, flag excessive visible copy and classify what each sentence is doing.
- **Rewrite Mode**: replace over-explained copy with shorter text or concrete UI structure.

When the user does not specify a mode, use Audit Mode first, then include Rewrite Mode recommendations for every issue.

## When Not To Use

Do not aggressively reduce copy when the surface is primarily:

- Documentation, tutorials, courses, legal disclosures, policy explanations, or support articles.
- Public marketing pages where persuasive narrative is the job.
- High-risk workflows where compliance, safety, finance, health, or destructive actions require explicit explanation.
- First-run onboarding where the user has no context and the next action is not inferable from the UI.

In those cases, reduce redundancy and improve structure, but preserve necessary explanation.

## Workflow

1. Identify the screen type: app workflow, dashboard, form, editor, empty state, onboarding, marketing, documentation, or settings.
2. Identify the primary user action for the screen.
3. Classify visible sentences with Copy Triage.
4. Apply the Copy Budget.
5. Replace paragraphs with UI structure where possible.
6. Report findings using the Output Format.

## Copy Triage

Classify each visible sentence:

- **Action copy**: helps the user complete the current task. Keep and shorten.
- **State copy**: explains data, progress, empty state, validation, or error. Keep near the state.
- **Decision copy**: helps the user choose between meaningful options. Keep, but anchor it to the choice.
- **Instructional copy**: explains obvious UI. Remove or move to tooltip/help.
- **Marketing copy**: describes product value instead of enabling action. Remove from app/work surfaces.
- **Redundant copy**: repeats headings, labels, buttons, or nearby visual structure. Remove.

If the sentence does not change what the user can understand, decide, or do, remove it.

## Copy Budget

Use these defaults unless the product context demands more:

- Screen: one primary heading and at most one supporting sentence.
- Section: short label or heading; avoid standalone explanatory paragraphs.
- Card: one short title plus optional metadata, status, or one-line result.
- Form field: label plus optional helper text only when format or consequence is not obvious.
- Empty state: one sentence, one primary action, optional secondary action.
- Tooltip: one sentence; never hide essential instructions required to complete the task.
- Button: action verb or verb phrase; avoid explanatory button labels.

## Severity

- **P1**: text blocks the primary workflow, hides the main action, or makes the screen read like documentation/marketing.
- **P2**: text slows scanning, repeats visible UI, or makes cards/forms/sections feel cluttered.
- **P3**: local microcopy can be shortened, moved, or made more specific.

## Replacement Rules

Prefer replacing text with structure:

- Use controls for choices: tabs, filters, segmented controls, toggles, menus.
- Use layout for meaning: grouped sections, columns, tables, timelines, side panels.
- Use data for explanation: sample rows, previews, defaults, placeholders.
- Use microcopy for context: labels, badges, captions, inline validation.
- Use progressive disclosure for non-essential help: tooltip, popover, help drawer, details panel.

## Output Format

For each finding:

```md
- Severity:
- Location:
- Problem:
- Fix:
- Suggested replacement:
```

End with:

```md
Top removals:
Top UI replacements:
Revised copy budget:
Residual risk:
```

When editing files, make the copy and layout changes directly after reporting the plan. Verify the result visually when a local app or screenshot path is available.
